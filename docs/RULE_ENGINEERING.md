# 敏感词审核规则制定指南

## 一、规则的定义

在敏感词审核系统中，"规则"是判定内容合规性的核心逻辑，它决定了：
- 哪些内容需要拦截
- 什么条件下触发不同级别的处理
- 如何平衡漏放率和误报率

---

## 二、规则类型

### 1. 关键词规则（最基础）

直接匹配敏感词库中的词条。

```yaml
# 示例：基础关键词配置
keywords:
  - "敏感词"
  - "违禁词"
  - "品牌词"
```

| 适用场景 | 优点 | 缺点 |
|----------|------|------|
| 明确违禁内容（政治、色情、暴恐） | 精确、可解释 | 无法识别变体 |

---

### 2. 变体规则（应对用户规避）

用户通过各种变体方式规避关键词检测。

| 类型 | 示例 | 规避原词 | 规则写法 |
|------|------|----------|----------|
| **谐音字** | "政腐" | 政府 | `{"pattern": "政.*腐", "type": "regex"}` |
| **拼音首字母** | "FK" | 反恐 | `{"pattern": "F[K\|k]", "type": "regex"}` |
| **特殊符号干扰** | "反✈️政府" | 反政府 | `{"pattern": "反[\\s\\S]*政府", "type": "regex"}` |
| **emoji替代** | "🔪" | 暴力 | `{"pattern": "[🔪🗡️💣]+", "type": "emoji"}` |
| **形近字** | "口乞" | 吃 | 需额外词库映射 |
| **拆字** | "女干" | 奸 | 需额外词库映射 |
| **简繁混用** | "繁體" | 简体敏感词 | 需统一归一化 |

**解决方案**：
- 正则表达式匹配变体模式
- 向量相似度识别语义相近内容
- 文字归一化预处理（繁→简、全角→半角）

---

### 3. 语义规则（上下文判断）

仅靠关键词无法判断的情况，需要结合上下文。

```json
{
  "rule": "政治人物负面关联",
  "conditions": [
    {"type": "keyword", "value": "领导人姓名"},
    {"type": "keyword", "value": "负面修饰词"},
    {"type": "relation", "value": "NEAR", "distance": 5}
  ],
  "action": "escalate_to_llm"
}
```

| 适用场景 | 实现方式 |
|----------|----------|
| 组合判断（同时出现多个词） | 条件组合逻辑 |
| 上下文推断（阴阳怪气） | LLM 推理 |
| 讽刺反讽识别 | 向量相似度 + LLM |

---

### 4. 权重规则（分级处理）

内容按风险等级分层处理：

| 级别 | 名称 | 示例 | 处理方式 |
|------|------|------|----------|
| **P0** | 禁止 | 色情、暴恐 | 直接拦截 |
| **P1** | 警告 | 软色情、擦边 | 人工审核 |
| **P2** | 关注 | 政治敏感 | 记录+告警 |
| **P3** | 提醒 | 疑似违规 | 通过但标记 |

## 三、规则制定流程

```
┌─────────────────────────────────────────────────────────────┐
│  1. 风险定义                                                │
│     确定哪些内容需要拦截（法规/业务/品牌）                    │
│     ↓                                                       │
│  2. 关键词提取                                              │
│     从违规案例中提取核心词                                   │
│     ↓                                                       │
│  3. 变体扩展                                                │
│     模拟用户规避手段（谐音、符号、拼音）                      │
│     ↓                                                       │
│  4. 规则测试                                                │
│     用历史数据验证召回率和误报率                              │
│     ↓                                                       │
│  5. 阈值调优                                                │
│     调整相似度阈值，降低漏放和误报                            │
│     ↓                                                       │
│  6. 持续迭代                                                │
│     根据新 case 更新规则                                     │
└─────────────────────────────────────────────────────────────┘
```

### 各阶段详细说明

#### 阶段 1：风险定义

**输入**：
- 法规要求（网络安全法、广告法、未成年人保护法）
- 业务规范（平台公约、社区准则）
- 品牌策略（品牌词保护、企业形象）

**输出**：
- 风险分类清单
- 各分类的处置方式

#### 阶段 2：关键词提取

**方法**：
- 历史违规case分析
- 同行公开词库参考
- 法规明确列表

#### 阶段 3：变体扩展

**模拟用户行为**：
- 谐音转换（口啤→口碑）
- 符号干扰（冲💣击）
- 拼音伪装（zf→政府）

#### 阶段 4：规则测试

**测试指标**：
```
召回率 = 检出敏感内容 / 实际敏感内容总数
误报率 = 误判正常内容 / 判定为敏感的内容总数
```

**目标**：召回率 > 95%，误报率 < 5%

#### 阶段 5：阈值调优

| 阈值降低 | 阈值提高 |
|----------|----------|
| 召回率↑ | 误报率↓ |
| 误报率↑ | 召回率↓ |

需要根据业务场景找到平衡点。

## 四、行业规则模板

### 电商行业

| 规则类型 | 示例 | 优先级 |
|----------|------|--------|
| **虚假宣传** | "最好"、"第一"、"全网最低" | P1 |
| **品牌词保护** | 竞品品牌名 | P2 |
| **违禁商品** | 仿真枪、处方药 | P0 |
| **导流信息** | 微信、QQ、第三方链接 | P1 |

### 在线教育

| 规则类型 | 示例 | 优先级 |
|----------|------|--------|
| **未成年保护** | 色情、低俗内容 | P0 |
| **不良价值观** | 暴力、犯罪 | P0 |
| **虚假宣传** | 夸大教学效果 | P1 |
| **侵权内容** | 盗版教材 | P1 |

### 金融行业

| 规则类型 | 示例 | 优先级 |
|----------|------|--------|
| **合规披露** | 风险提示缺失 | P1 |
| **敏感信息披露** | 客户隐私 | P0 |
| **违规承诺** | "保本"、"高收益" | P0 |
| **监管红线** | 监管禁用词 | P0 |

## 五、规则优先级机制

当多条规则同时匹配时，按优先级处理：

```
P0（禁止） > P1（警告） > P2（关注） > P3（提醒）
```

**冲突处理策略**：
- 高优先级规则覆盖低优先级
- 多规则同时触发时取最高风险等级
- 支持规则组（AND/OR 组合）

## 六、Jetwash 中的规则实现

### 配置示例

```yaml
# config.yaml 中的敏感词配置
sensitive:
  level_1:  # Layer 1：精确匹配（AC自动机）
    categories:
      - 政治敏感
      - 色情低俗
      - 暴恐违法
    match_mode: "exact"

  level_2:  # Layer 2：向量相似度匹配
    threshold: 0.85
    categories:
      - 变体词
      - 谐音词

  level_3:  # Layer 3：LLM 推理
    prompt_template: |
      判断以下内容是否违规：
      {{.text}}

      违规类型包括：政治敏感、色情低俗、暴力恐怖...
    confidence_threshold: 0.9
```

### 自动学习机制

Jetwash 支持 LLM 发现新词后自动入库：

```go
// 新词自动入库流程
1. LLM 判断内容违规
2. LLM 提取敏感词
3. 敏感词写入数据库
4. AC 自动机增量更新
5. 生效延迟 < 1ms
```

## 七、常见问题与解决方案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| **变体太多，词库爆炸** | 穷举式变体扩展 | 改用向量检索识别语义相近词 |
| **误报率高** | 规则过于严格 | 组合条件判断 + LLM 二审 |
| **新词发现滞后** | 人工更新效率低 | 自动学习机制（Jetwash 已实现） |
| **规则冲突** | 多规则重叠 | 优先级 + 并集/交集策略 |
| **上下文歧义** | 单独词无意义 | LLM 推理判断语境 |
| **多语言混排** | 中文夹杂外文 | 归一化 + 多语言词库 |

## 八、规则治理建议

### 定期审查

| 频率 | 内容 |
|------|------|
| **每日** | 新增违规 case 分析 |
| **每周** | 规则效果评估、阈值调整 |
| **每月** | 词库全面审查、过期词清理 |
| **每季度** | 行业法规变化同步 |

### 灰度发布

新规则上线前，建议：
1. 先用 5% 流量测试
2. 对比新旧规则效果差异
3. 确认无问题后全量上线

---

> 规则制定是持续运营的过程，需要根据业务发展和用户行为不断迭代优化。
